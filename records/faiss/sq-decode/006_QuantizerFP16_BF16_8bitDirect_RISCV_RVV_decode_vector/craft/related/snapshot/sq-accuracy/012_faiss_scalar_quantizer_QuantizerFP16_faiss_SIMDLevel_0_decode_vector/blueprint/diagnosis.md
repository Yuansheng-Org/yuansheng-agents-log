# Diagnosis

Software: faiss
Testcase: sq-accuracy
Function: faiss\_scalar\_quantizer\_QuantizerFP16\_faiss\_SIMDLevel\_0\_decode\_vector
Verdict: `confirmed`

Summary: QuantizerFP16\<SIMDLevel::NONE\>::decode\_vector is bottlenecked by a scalar, branch-per-lane software FP16-\>FP32 conversion loop: it inlines decode\_fp16 (fp16-inl.h) as integer bit-decode that per element loads the FP16 halfword (lhu 0x389672), isolates exponent/sign with shifts and ANDs, branches on the zero/subnormal and inf/nan special cases (including the fmv.w.x/fsub.s/fmv.x.w float round-trip at 0x389658-0x389666), ORs the sign, and stores FP32 (sw 0x38969e); all three sampled addresses are inside this body, while the build ISA (v1p0+zvfhmin, zvl128b) provides the RVV widening conversion vfwcvt.f.f.v that the loop omits.

## Findings
- `probable` (root cause, medium) QuantizerFP16\<SIMDLevel::NONE\>::decode\_vector is bottlenecked by a scalar, branch-per-lane software FP16-\>FP32 conversion loop: it inlines decode\_fp16 (fp16-inl.h) as integer bit-decode that per element loads the FP16 halfword (lhu 0x389672), isolates exponent/sign with shifts and ANDs, branches on the zero/subnormal and inf/nan special cases (including the fmv.w.x/fsub.s/fmv.x.w float round-trip at 0x389658-0x389666), ORs the sign, and stores FP32 (sw 0x38969e); all three sampled addresses are inside this body, while the build ISA (v1p0+zvfhmin, zvl128b) provides the RVV widening conversion vfwcvt.f.f.v that the loop omits.
  Reasoning: Annotate shows the decode loop executing ~15 instructions plus 3 branches per element with no vector instruction; fp16-inl.h confirms decode\_fp16 handles per-lane special values with conditional selects; fp16.h resolves to the fp16-inl fallback on riscv64 (no \_\_F16C\_\_/\_\_aarch64\_\_); metadata Tag\_RISCV\_arch proves v1p0+zvfhmin in the build, and isa-extensions.md routes v-present FP16-to-FP32 conversion to rvv\_precision\_conversion\_kernels (vfwcvt.f.f.v fast path). Shared sample evidence: lhu, sw, addi each 33.33%.
- `confirmed` (contributing factor, high) faiss ships no RISC-V vector specialization of the FP16 quantizer decode: QuantizerFP16 has only the generic SIMDLevel::NONE scalar template (used here) plus x86-intrinsic AVX2 and AVX512 specializations (reconstruct\_8\_components via \_mm\_cvtph\_ps / AVX512), so on riscv64 neither the vector conversion vfwcvt.f.f.v nor any RVV widen path is ever engaged for decode\_vector, guaranteeing the branchy scalar loop.
  Reasoning: quantizers.h defines QuantizerFP16\<SIMDLevel::NONE\>::decode\_vector as a plain per-element decode\_fp16 loop and lets higher SIMDLevels inherit from NONE unless specialized; sq-avx2.cpp and sq-avx512-impl.h define the only SIMD specializations of QuantizerFP16, both behind x86 intrinsics; no RVV .cpp specialization exists in the scalar\_quantizer directory search results; metadata confirms the riscv64 build arch and v+zvfhmin ISA.

## Gaps
- `baseline_gap_measurement`: Only 3 cpu-clock samples were captured for the entire decode\_vector function across the run, so the function's dynamic hotspot share within sq-accuracy and any benefit upper bound are weakly measured; per-call instruction count is known from disassembly but per-call cycle cost is not.
- `source_context_gap_analysis`: Runtime hardware ISA beyond the build tags is unverified: metadata provides Tag\_RISCV\_arch proving the build enables v1p0+zvfhmin, but no /proc/cpuinfo isa line or hwprobe evidence confirms the benchmark host actually executes v and zvfhmin.
- `implementation_shape_gap_actionability`: The call context of decode\_vector inside sq-accuracy is not evidenced (which benchmark phase generated the 3 samples, and how many reconstruction calls occurred), so end-to-end benchmark benefit of a vector decode cannot be quantified.

## Actions
- `conditional`: Add an RVV fast path to QuantizerFP16 decode\_vector gated on \_\_riscv\_v && \_\_riscv\_zvfhmin: per iteration vsetvl\_e16m\* on remaining count, vle16 load of FP16 codes, vfwcvt.f.f.v widening FP16-\>FP32 (native IEEE handling of normals, denormals, ±0, ±Inf, NaN), vse32 store, with tail handling for d % VL and the existing scalar decode\_fp16 loop retained as the fallback; add a masked/narrow repair only if bit-exact NaN-payload/sNaN parity with decode\_fp16 is required.
- `conditional`: Add an RVV-enabled QuantizerFP16 decode specialization to the faiss scalar\_quantizer dispatch so riscv64 builds no longer default decode\_vector to the SIMDLevel::NONE scalar body: introduce a QuantizerFP16 (or decode\_vector) path selected under \_\_riscv\_v && \_\_riscv\_zvfhmin that performs vle16/vfwcvt.f.f.v/vse32 widening conversion, modeled on the existing AVX2/AVX512 reconstruct\_8\_components specializations, with a scalar fallback for other builds.
