  Reasoning: Distance-computers.h compute\_distance is a scalar reduction loop (acc += q\[i\]\*reconstruct(code,i)) auto-vectorized by the RISC-V backend. Disassembly at 0x7aae4c-0x7aae8a processes only 4 bytes per iteration (vsetvli a5,a4,e8,mf4; VLMAX=e8/mf4=4 on VLEN128). Per iteration it runs an ordered vfredosum.vs and round-trips the accumulator through the FP scalar register file (0x7aae5c vfmv.s.f, 0x7aae86 vfmv.f.s), plus 4 vsetvl-family instructions (0x7aae4c, 0x7aae58 vsetivli VL=1, 0x7aae60 restore 24.98%, 0x7aae6c SEW switch). This is the rvv\_register\_group\_utilization failure form (LMUL below frontier -\> excessive iterations of vsetvl, reduction round-trip, and branch).
- `confirmed` (contributing factor, high) A contributing factor is the per-block horizontal reduction: vfredosum.vs + vfmv.f.s fa0 (49.64%) + next-iteration vfmv.s.f round-trips the accumulator through the FP scalar register file on the loop-carried critical path for every 4-element block, serializing reduction latency instead of keeping vector accumulators that are merged once at the end.
  Reasoning: The loop executes a horizontal reduction for every 4-element block: 0x7aae82 vfredosum.vs v2,v1,v2 then 0x7aae86 vfmv.f.s fa0,v2 extracts to scalar, next iteration 0x7aae5c vfmv.s.f v2,fa0 re-splats. Source semantics (distance\_computers.h:34-39) confirm a standalone dot-product-like additive accumulation with no matmul microkernel, so widening-reduction ownership excludes rvv\_floating\_point\_matmul\_and\_gemv\_kernels.
