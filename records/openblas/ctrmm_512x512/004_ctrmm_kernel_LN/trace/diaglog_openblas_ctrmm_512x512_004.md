## Phase 4 — Root-cause blueprint / 根因蓝图：ctrmm_kernel_LN

纳入蓝图的两个 pattern 均点名 Phase 3 通过 gate 的 row：primary ← `rows-operator-rvv.md` 行 25（RVV Floating-Point Matmul and GEMV Kernels）；supporting ← `rows-operator-rvv.md` 行 14（RVV Complex Arithmetic Kernels）。

**1. Root cause**

`ctrmm_kernel_LN`（来自 autogenerated `kernel/riscv64/ctrmm_kernel_8x8_zvl256b.c`，LMUL=1/M=8/N=8/complex）的 main-pass k-loop（[15f0a–1601e]）对每个复数乘积执行 **6 个 vector op 的 tmp 链**：`tmp = vfmul.vf(A0i, Bi)` → `tmp = vfmsac/vfmacc.vf(tmp, Br, A)` → `ACC = vfadd.vv(ACC, tmp)`（每轮 8 列 = 48 个 vector op），而 RVV 允许以 **4 个 fused op 直接累积进成对 accumulator**：`acc_r = vfmacc(acc_r, Br, Ar); acc_r = vfmsac(acc_r, Bi, Ai); acc_i = vfmacc(acc_i, Br, Ai); acc_i = vfmacc(acc_i, Bi, Ar)`（每轮 32 个 vector op）。16 条 `vfadd.vv`（15f7a–16016）与 16 条 `vfmul.vf`（15f26–15f86）为可消除的中间形态开销。这与 FP-matmul pattern 的机制句一致——"FMA accumulator 依赖过长"与"沿输出列向量化、增加合法独立 accumulator、保持明确的 FP 累加语义"（依据 `patterns/rvv_floating_point_matmul_and_gemv_kernels.md` §Why this is slow / §The fix），并由 complex-arithmetic pattern 给出精确修复形态——"real/imag 在同一 strip-mined traversal 中共同存活，使用独立 accumulator 隐藏依赖"（依据 `patterns/rvv_complex_arithmetic_kernels.md` §The fix 的成对 accumulator 伪代码：`acc_r = rvv_fmacc(acc_r, ar, xr); acc_r = rvv_fnmsac(acc_r, ai, xi); acc_i = rvv_fmacc(acc_i, ar, xi); acc_i = rvv_fmacc(acc_i, ai, xr)`）。

次级机制（同一因果链）：vector 寄存器预算 32/32 耗尽（16 ACC + 2 A + 14 tmp；源码注释自述 "2 vector regs to hold A array contents, 16 regs to hold values accumulated over k, leaving 14 vector registers for temporaries"）。后果 ① 每轮 16 条 `flw` 重载仅依赖 (j,k) 的 B 标量（B 跨 i 块不变，M=512 → 64 个 i 块全部重载，i-loop 结构无法利用该复用）；后果 ② 当前 tmp 结构下 LMUL=2 之类更高寄存器组不合法（kernel-conventions §2：`LMUL * peak_live_vectors <= 32` 不满足），锁定 8×8/m1 tile 形状。

**2. The fix / 修复方式**

修复对象 = autogenerated kernel 的 k-loop 复数 MAC 指令选择（源行 215–262 对应的 intrinsic 序列），方向为直接成对 accumulator FMA 累积：

```
// Before（每复数乘积 6 vector op；源行 143–262 的形态）：
tmp_r = vfmul(A0i, B_i);            // 1 mul
tmp_i = vfmul(A0r, B_i);            // 2 mul
tmp_r = vfmsac(tmp_r, B_r, A0r);    // 3 fma（NN: VFMACC_RR）
tmp_i = vfmacc(tmp_i, B_r, A0i);    // 4 fma（NN: VFMACC_RI）
ACC_r = vfadd(ACC_r, tmp_r);        // 5 add
ACC_i = vfadd(ACC_i, tmp_i);        // 6 add

// After（每复数乘积 4 vector op，直接累积）：
ACC_r = vfmacc(ACC_r, B_r, A0r);    // +Ar*Br
ACC_r = vfmsac(ACC_r, B_i, A0i);    // -Ai*Bi
ACC_i = vfmacc(ACC_i, B_r, A0i);    // +Ai*Br
ACC_i = vfmacc(ACC_i, B_i, A0r);    // +Ar*Bi
```

- 适用前提：各 conj/trans 变体（NN/NT/TN/TT 及 C/R）按 S0–S3 符号表保留现有符号语义，仅把 "mul → fma → add" 折叠进成对 FMA；需在 autogenerator（生成 `ctrmm_kernel_8x8_zvl256b.c` / `cgemm_kernel_8x8_zvl256b.c` 的脚本）层面修改，而非手改生成文件。
- correctness contract 不可破坏：复数乘加的数值结果（各变体符号、Hermitian 共轭路径）、`alpha`（alphar/alphai）epilogue 语义、C 的 interleaved 布局与 `ldc` 步长、NaN/Inf/±0/subnormal 传播；FP 累加顺序会改变（每乘积 3 次舍入 → 2 次 fused 舍入），需按 OpenBLAS 允许误差合同对照 reference 验证（pattern §Verification：对照 reference 检查 FP32 累加精度、FMA contraction、NaN/Inf/±0 与允许误差）。
- 限制/风险：直接累积使每个 ACC 链每 k 变为 2 个串行 FMA（原为 1 个 vfadd），单链 latency 略增；但 16 个独立 ACC 链提供 16 路 ILP，OoO X100 上 issue-throughput 主导，净收益为正；LMUL/tile 结构（8×8/m1 固定 VL）不改动；register 预算降至 18/32（16 ACC + 2 A），为后续 B 复用/tile 扩展腾出空间（本次不实施）。
- 修复后预期 Profile signals：k-loop 内 `vfadd.vv` 16→0、`vfmul.vf` 16→0，vector op 48→32（−33%），k-loop 指令数 ≈69→≈53（−23%），函数总指令数与区间 sample 占比随之下移；`vfmacc.vf/vfmsac.vf` 仍为区间主体。
