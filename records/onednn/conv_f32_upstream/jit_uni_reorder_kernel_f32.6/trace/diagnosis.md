# Diagnosis

Software: onednn
Testcase: conv\_f32\_upstream
Function: jit\_uni\_reorder\_kernel\_f32.6
Verdict: `confirmed`

Summary: The f32-\>f32 reorder kernel jit\_uni\_reorder\_kernel\_f32.6 is an already-vectorized copy loop whose LMUL=m1 (SEW=e32) on VLEN=128 delivers only VLMAX=4 elements per vector step, forcing four 9-instruction inner iterations to copy each 16-element row and 16 per call; the loop-carried pointer-advance chain (vsetvli-\>mul-\>add-\>next vle) serializes the tiny 16-byte steps, concentrating 88.98% of function samples on the address-scaling mul at 0xfc.

## Findings
- `confirmed` (root cause, high) The f32-\>f32 reorder kernel jit\_uni\_reorder\_kernel\_f32.6 is an already-vectorized copy loop whose LMUL=m1 (SEW=e32) on VLEN=128 delivers only VLMAX=4 elements per vector step, forcing four 9-instruction inner iterations to copy each 16-element row and 16 per call; the loop-carried pointer-advance chain (vsetvli-\>mul-\>add-\>next vle) serializes the tiny 16-byte steps, concentrating 88.98% of function samples on the address-scaling mul at 0xfc.
  Reasoning: The sampled kernel is jit\_uni\_reorder\_kernel\_f32\_t::emit\_pure\_copy\_core (f32-\>f32 unit-stride copy). Source uses vsetvli(reg\_vl\_, reg\_rem\_, SEW::e32, LMUL::m1) so VLMAX=4 on VLEN=128 (vlenb=16, C920v2). The 16-element node\[0\] therefore needs 4 inner iterations per row and 4 rows (node\[1\].n=4) give 16 vector steps per call, each advancing only 16 bytes. 88.98% of the 118 function samples land on the loop-carried pointer-offset mul at 0xfc; the loop body is 6 scalar bookkeeping instructions (2 mul, 2 add, sub, j) around 2 vector instructions. LMUL=m1 is far below the legal frontier: only one vector register is live (v8) plus transients, so LMUL\*peak\_live \<= 32 holds for m4 (VLMAX=16 = node\[0\].n), collapsing the inner loop to one iteration per row.
- `probable` (contributing factor, medium) The pointer advance inside the hot copy loop is expressed as per-iteration index scaling (two identical mul t3\*4 plus two adds) instead of induction-variable pointer increments with a precomputed end-pointer comparison; in the steady state VL is constant (VLMAX=4, 16 bytes), so this is 4 instructions of redundant loop-control work per 16-byte vector step.
  Reasoning: Disassembly shows the pointer advance recomputed every iteration as mul t0,t3,a4; add t4,t4,t0; mul t0,t3,a5; add t5,t5,t0 (a4==a5==4): index scaling of VL\*4 twice per 16-byte step. Source emit\_pure\_copy\_core emits the same mul(reg\_tmp0\_,reg\_vl\_,reg\_istride\_); add; mul; add; sub; j sequence. With VL at VLMAX=4 in steady state the advance is a constant 16 bytes, so two induction variables incrementing by addi 16 plus an end-pointer comparison replace 4-6 scalar instructions per iteration; the same leverage also removes the duplicate same-operand mul.
- `probable` (contributing factor, medium) The JIT emitter (jit\_uni\_reorder\_kernel\_f32\_t::emit\_pure\_copy\_core) always emits the fixed LMUL=m1 loop shape with duplicate same-operand mul pairs (a4==a5==4) and sub/j bookkeeping regardless of the actual geometry (node\[0\]=16, VLEN=128), so the code-generation contract failed to specialize the hot copy loop.
  Reasoning: The hotspot lies in code emitted by oneDNN's RISC-V JIT reorder emitter. emit\_pure\_copy\_core unconditionally emits the m1 loop with two identical muls (a4==a5==4), a sub counter and a j back-edge regardless of VLEN or node\[0\].n: the emitter/representation contract never specialized the loop to the small unit-stride copy geometry, so every emitted instruction lands directly on the workload's execution path.

## Gaps
- `baseline_gap_measurement`: The three vector instructions in the inner loop (0xf0, 0xf4, 0xf8) are printed as raw .insn words because the toolchain disassembler in this build lacks V-extension support, so the vtype/LMUL was confirmed from the emitter source (SEW::e32, LMUL::m1) rather than from decoded instructions.
- `baseline_gap_measurement`: Whole-run share of jit\_uni\_reorder\_kernel\_f32.6 (rank 010) is not quantified; only the within-function sample distribution (118 samples, 88.98% at 0xfc) is available, so the workload-level benefit upper bound is unmeasured.
- `evidence_gap_confidence`: build\_isa is null in metadata and the benchdnn ELF build attributes list no V extension while the runtime CPU supports RVV 1.0, so dispatch-level confirmation that this JIT kernel (rather than a scalar reference reorder) is the executing path for every sampled call is incomplete.
- `source_context_gap_missing_source`: Local source evidence is unavailable at src/cpu/generic.
- `source_context_gap_missing_source`: Local source evidence is unavailable at src/cpu/rv64/xbyak.
- `source_context_gap_missing_source`: Local source evidence is unavailable at src/cpu/riscv64.

## Actions
- `conditional`: In jit\_uni\_reorder\_kernel\_f32\_t::emit\_pure\_copy\_core (src/cpu/rv64/reorder/jit\_uni\_reorder\_kernel.cpp) select LMUL from runtime VLEN and node\[0\].n instead of the hardcoded m1: for e32 on VLEN=128, LMUL=m4 yields VLMAX=16 equal to node\[0\].n, collapsing the four inner iterations per 16-element row into one; enforce LMUL \* peak\_live\_vectors \<= 32 (only one live vector v8 plus transients live), validate group alignment, and retain an m1 fallback when the budget or vlenb is unknown. This is an emitter emission change, not a source-level loop rewrite.
- `conditional`: In emit\_pure\_copy\_core's vl-loop, replace the per-iteration index scaling (mul reg\_tmp0\_,reg\_vl\_,reg\_istride\_; add reg\_addr\_,reg\_addr\_,reg\_tmp0\_ and the oside pair) with induction-variable pointer increments: precompute src\_end/dst\_end = base + n\*stride once before the loop, advance both pointers by a constant step (addi VLMAX\*4 = 16 bytes on VLEN=128 e32/m1) on full-VL iterations, compare pointers against the precomputed ends, and keep a mul/VL-based advance only for the partial tail. When reg\_istride\_==reg\_ostride\_ (both 4 here), emit one shared offset instead of two identical muls.
- `conditional`: Harden the emitter contract in emit\_pure\_copy\_core so the generated shape is derived from the actual geometry: (a) choose LMUL from runtime VLEN and node\[0\].n (m4 on VLEN=128, one iteration per 16-element row), and (b) when reg\_istride\_==reg\_ostride\_ (both 4 here), emit one shared pointer-advance offset instead of two identical muls, using a single addi on full-VL steps. Keep the generic m1 mul-based shape for non-unit, non-pure-copy, or attribute-bearing configs so other reorders are untouched.
