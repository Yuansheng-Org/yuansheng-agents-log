## 二、性能数据（-O3）

| 归约器 | 基线 | 增量进位 | 比值 |
|---|---:|---:|---:|
| `seq_reduce_assign<red::sum>` | 13.72 ms | **9.32 ms** | **1.47×** |
| `seq_reduce_assign<mshadow_op::sum>` | 13.56 ms | **9.12 ms** | **1.49×** |
| `seq_reduce_assign_block` | 3.417 ms | **2.345 ms** | **1.46×** |

> **测量形状不统一（照实标注，勿混读）**：
> 前两行（序号 72）与 `-O2` 表均为 **M=1024 / outN=1024 / 120 轮**；
> block 行（序号 78）为 **M=4096 / outN=64 / 200 轮**，且其对照 `p003` 实测 **3.4173 ms（与 base 完全相同）**
> —— 这既是"72 对 block 分支无影响"的直接证据，也说明该行**不能与前两行并排比较**。

**-O2 复核（同一排序，M=1024/outN=1024）**：

| 归约器 | 基线 | 增量进位 | 比值 |
|---|---:|---:|---:|
| `red::sum` | 13.01 ms | 9.43 ms | **1.38×** |
| `mshadow_op::sum` | 16.51 ms | 9.14 ms | **1.81×** |

**其他形状同向（M≠1024）**：`M=1000` **1.44× / 1.66×**；`M=4096` **1.38× / 1.80×**（`red::sum` / `mshadow_op::sum`）。
源文档另记"非 2 的幂与奇数形状（`M=1000`、`M=97`）"确认有效益。

> 序号 72 的作用面是 `!use_omp` 分支（`N >= thread_count` 时走），序号 78 是 OpenMP block 分支。
> 两者**互补而非重复**：实测 72 对 block 分支**完全无影响**，block 分支由 78 单独拿 1.46×。
> `mshadow_op::sum` 在 -O2 下比值更高（1.81×）而 -O3 下（1.49×）回落，系编译器对该 TU 的既有优化程度不同所致，两组数据均如实保留。

## 三、生成代码（机制证据：内层循环的除法/取余条数）

rv64gcv、GCC 15.1：

| 函数 | `div` | `rem` |
|---|---|---|
| `seq_reduce_assign<red::sum>` | 4 → **2** | 6 → **3** |
| `seq_reduce_assign<mshadow_op::sum>` | 4 → **2** | 6 → **3** |
| `seq_reduce_assign_block`（两者） | 2 → **0** | 3 → **0** |

块版本能把除法/取余清零，是因为整块的坐标只在**进入时 seed 一次**（`unravel(start, rshape)`）。

## 四、正确性（收益合法性的前提）

| 检查项 | 结果 |
|---|---|
| 输出比特 | 所有构建、所有形状下**逐位相同** |
| 摘要 | 原始输出比特的 FNV-1a 完全一致（例：`M=1024/outN=1024`、`M=1000/outN=500`、`M=97/outN=13`） |
| 索引等价性 | 增量进位式索引另经**穷举 + 随机化**等价测试比对原实现 |
| 边界守卫 | block 版本有 `if (len > 0)` 守卫，零尺寸归约形状不会在 `unravel` 里触发除零 |

## 五、收益结论与复核要点

| 项 | 结果 |
|---|---|
| 是否 RISC-V 专属 | **否**。**缺硬件整数除法器**的目标收益最大（x86/aarch64 亦有收益） |
| **序号 72**（B） | -O2 **1.38×** / -O3 **1.47×**（`red::sum`）；-O2 **1.81×** / -O3 **1.49×**（`mshadow_op::sum`） |
| **序号 78**（C） | **1.46×**（block 分支），且 72 对该分支无影响 ⇒ 互补非重复 |
| 序号 73 / 79 | **重复件**（73 ≡ 72、79 ≡ 78 逐字节相同），**不单独提交** |
| 数值影响 | **逐位相同** |
| CI 覆盖 | 72：✅ 验收用例 `sum(data(1024,1024), axis=1)` 的 N=1024 ≥ thread_count ⇒ 正好命中 `use_omp=false`<br>78：⚠️ 走 `use_omp=true`，**固定用例覆盖不到**（全类别扫描可能命中）——**不要**用"CI 通过"当作它被测到的证据 |
| 风险 | 低。纯索引等价变换；block 版带 `len > 0` 除零守卫 |

## 六、数值口径

- 本节所有比值均已由原始中位数复核，与源文档 `mxnet_9补丁复核结论.md` / `mxnet_PR描述_提交材料.md` **逐项吻合**：
  - -O3：13.72/9.32 = 1.472、13.56/9.12 = 1.487、3.4173/2.3447 = **1.457**（↔ 文档 1.47 / 1.49 / 1.46 ✅）
  - -O2：13.01/9.43 = 1.380、16.51/9.14 = **1.806**（↔ 文档 1.38 / 1.81 ✅）
- **合计收益**：`red::sum` 116→120 insns、`mshadow_op::sum` 107→114 insns —— **指令数略增**（进位逻辑本身要几条指令），
  但 `div`/`rem` 从 4/6 降到 2/3，真正的成本项被消掉。**不要**用"指令数变少"描述本补丁。
- **块版本单独给出**：`seq_reduce_assign_block` 的 1.46× 是**另一条分支**的成绩，与前两行不同形状，
  引用时须连同形状一起给出（见 §二 注）。
